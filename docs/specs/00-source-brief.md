# Исходное ТЗ (2026-11-13)

Текст ТЗ без изменений. Решения грилинга, которые его уточняют или меняют, — в спеках `stage-N-*.md` и в `docs/adr/`. Где спека и ТЗ расходятся, верна спека.

# Задача

Ты строишь систему-помощник для мебельщика-одиночки, который делает кухни
на заказ: сам общается с клиентом, закупает материалы и фурнитуру, пилит,
кромит, сверлит и собирает на объекте. Работай в текущей папке.

Система: данные мастерской (YAML) + движок расчёта (Python) + скиллы Claude,
которые вызывают движок. Пройди все этапы ниже по порядку.

# Принципы

1. Все числа считает код. Ты пишешь движок и вызываешь его, но никогда
   не считаешь размеры, количества и цены «в голове».
2. Формулы и правила конструкции живут только в движке и в
   workshop/construction.yaml. Скиллы формул не содержат.
3. project.json заказа — единственный источник правды. У него есть номер
   версии; всё, что посчитано из проекта, хранит версию-источник.
4. Мок-данные. Каждый YAML в workshop/ содержит `mock: true`. Если в расчёте
   использован хоть один мок-файл, любой вывод (CLI, PDF, HTML, JSON)
   получает заметную пометку «МОК-ДАННЫЕ — НЕ ДЛЯ КЛИЕНТА». В PDF — водяной
   знак. Список всего, что надо заменить, веди в MOCKS.md.
5. Каждая задача: код → тесты → зелёные тесты → git commit с номером задачи
   → отметка в PROGRESS.md.
6. Если правило неоднозначно — выбери разумный вариант, запиши его в
   DECISIONS.md с пометкой «ПРОВЕРИТЬ МАСТЕРУ» и продолжай.
7. В начале каждой новой сессии сначала прочитай PROGRESS.md и DECISIONS.md
   и продолжай с первой незакрытой задачи.
8. На вехах 1 и 2 остановись, покажи результаты (пути к PDF, ключевые
   цифры) и дождись подтверждения.

# Технологии

- Python 3.11+, зависимости через uv
- pydantic — схемы проекта, деталей, сметы; экспорт JSON Schema
- pyyaml — данные мастерской
- rectpack — раскрой (только гильотинные алгоритмы)
- reportlab — PDF
- pytest — тесты
- three.js с CDN — 3D в одном HTML-файле
- Интерфейс движка — CLI `kitchen` (typer или argparse), его вызывают скиллы

    wall_door, wall_lift, wall_hood, wall_dryer.

1.6 Проверки с понятными сообщениями (значение и предел): сумма модулей
