# Этап 5. Проект и 3D

Статус: `ready-for-agent`
Источник: `00-source-brief.md`, этап 5; ADR 0001, 0002.
Зависит от: этап 1 (детали с положениями), этап 0 (бриф и версии в БД), этап 2 (учёт выводов).

## Problem Statement

Клиенту трудно представить кухню по списку модулей, а мастеру — проверить, что модули встали в угол и не налезают друг на друга. Первая раскладка после замера занимает у мастера вечер. После правок проекта мастер не знает, какие PDF уже не соответствуют проекту.

## Solution

Движок собирает 3D-модель кухни из деталей и их положений в один HTML-файл, который открывается на телефоне. По брифу и замеру код по правилам строит несколько черновиков раскладки, а агент только предлагает и объясняет варианты. `kitchen status` показывает выводы, посчитанные из старых версий проекта.

## User Stories

1. Как мастер, я хочу один HTML-файл с 3D-моделью кухни, чтобы отправить его клиенту или открыть на объекте.
2. Как мастер, я хочу вращать и приближать модель пальцами на телефоне и мышью на компьютере.
3. Как мастер, я хочу кнопку «скрыть фасады», чтобы показать наполнение.
4. Как мастер, я хочу по нажатию на модуль подсвечивать его и видеть метку и размеры.
5. Как мастер, я хочу, чтобы модель строилась из тех же деталей, что идут в раскрой, чтобы картинка не врала.
6. Как мастер, я хочу видеть стены, пол и столешницу для ориентира.
7. Как мастер, я хочу пометку мока в HTML, пока данные мок.
8. Как мастер, я хочу черновик раскладки из брифа и замера: зоны (хранение, мойка, готовка), стандартные ширины, мойка у воды, без верхних у окна.
9. Как мастер, я хочу несколько вариантов раскладки, проверенных теми же проверками этапа 1.
10. Как мастер, я хочу, чтобы выбранный вариант стал версией проекта только по моей команде.
11. Как агент, я хочу получать варианты в JSON с объяснением правил, чтобы предложить их мастеру, не придумывая раскладку сам.
12. Как мастер, я хочу, чтобы `kitchen status` показывал, какие выводы устарели относительно текущей версии, и какой командой их пересчитать.

## Implementation Decisions

### 5.1 — 3D
- Движок раскладывает модули по стенам в координатах комнаты (угол, угловые смещения, пенал в обоих рядах, высоты рядов: низ на опорах, верх — правило МОК «верх верхних = верх пенала») и переводит положения деталей из системы модуля в систему комнаты.
- HTML один файл: three.js с CDN с точной закреплённой версией, данные деталей встроены JSON, OrbitControls с касаниями, кнопка «скрыть фасады», выбор модуля нажатием с подсветкой и подписью, плашка мока.
- Команда `kitchen 3d`; вывод регистрируется с версией-источником.

### 5.2 — Черновик раскладки
- Вход: бриф заказа из БД и размеры замера (стены, окно, вывод воды, вентканал, техника).
- Код по правилам: стандартные ширины модулей (новый ключ `construction.yaml`, МОК), мойка у вывода воды, ПММ рядом с мойкой, варочная с рабочими зонами по сторонам, пенал у края стены, без верхних модулей над окном, сумма ряда = длина стены.
- Выход: несколько вариантов проекта с объяснением, каждый прошёл проверки этапа 1.6. `kitchen layout <заказ>` печатает варианты; `kitchen layout <заказ> --pick N` импортирует выбранный как новую версию.

### 5.3 — Устаревшие выводы
- По учёту выводов (этап 2): вывод устарел, если его версия-источник меньше текущей версии проекта.
- `kitchen status` добавляет в `status.md` раздел «Устарело» с видом вывода, версией-источником и командой пересчёта.

## Testing Decisions

- Через `kitchen.api`: положения модулей заказа Петрова не пересекаются, угловые модули стоят в углу, пенал занимает оба ряда; каждая деталь в комнатных координатах лежит внутри своего модуля.
- HTML: содержит встроенный JSON со всеми маркировками, ссылку на three.js с точной версией, плашку мока.
- Раскладка: на брифе с окном и выводом воды каждый вариант проходит проверки, мойка у воды, над окном нет верхних; `--pick` создаёт версию, без `--pick` версий не прибавляется.
- Устаревшие выводы: после импорта v2 выводы v1 отмечены, после пересчёта — нет.
- Работа 3D на телефоне — `manual`.

## Out of Scope

- Фотореалистичный рендер, текстуры материалов.
- Редактирование проекта в 3D.
- ИИ, который сам строит раскладку.
