# Хотфикс. Защита от неверного ввода

Статус: `ready-for-agent`
Источник: полное ревью `docs/reviews/2026-11-15/` (сводка — `README.md`).
Делается до тикета 17.

## Problem Statement

На верных данных движок считает верно, но неверный ввод (опечатка в YAML, отрицательное число, незнакомый шаблон, файл в другой кодировке) либо роняет команду с трейсбеком, либо даёт правдоподобный, но неверный результат: отрицательные детали и фурнитуру, пропил меньше настоящего, лишние версии проекта. Мастер такую ошибку не заметит, пока деталь не выйдет не в размер.

## Solution

Каждый неверный ввод отклоняется при загрузке или проверке русской ошибкой с файлом, ключом или модулем. Ни одна команда `kitchen` не завершается трейсбеком. Числа мастерской и проекта ограничены типами и диапазонами в моделях; правило живёт в одном месте.

## Implementation Decisions

- **Пропил (решение мастера):** дробный пропил округляется вверх до целого мм и считается так во всём раскрое; результат раскроя несёт предупреждение «пропил 3.2 мм учтён как 4 мм» (текст, JSON, карта раскроя). Целый пропил — без предупреждения. `обрезка_по_периметру`, `макс_длина_реза` и размеры листа — строго целые, дробное — ошибка загрузки. `round()` над полями мастерской в коде раскроя не остаётся; проверка поля листа (`checks.part_fit_findings`) и раскрой берут одни и те же числа.
- **Версия проекта** создаётся, только если изменился нормализованный проект: написание поля `order` и запись целого числа как `600.0` версию не создают. Версии, уже записанные в БД со старым хешем, при повторном импорте того же файла новую версию не создают.
- **Размеры проекта:** габариты модуля и ниши — больше нуля, `shelves` — не меньше нуля; нарушение — ошибка схемы. Шаблон, который при данных габаритах строит деталь с неположительным размером, — находка `module_build`, импорт отклоняется.
- **Числа мастерской:** цены, ставки, нормы, доли, упаковки — неотрицательные (упаковка и шаги — больше нуля), без `inf` и `nan`; вилка быстрой оценки — положительная и по возрастанию. Сообщения — по-русски, без английского хвоста pydantic.
- **YAML:** повторный ключ — ошибка загрузки; повторный `id` в `hardware.yaml`, `materials.yaml`, `appliances.yaml` — ошибка загрузки; файл не в UTF-8 — русская ошибка с именем файла; BOM допускается (и в YAML, и в `project.json`/`brief.json`).
- **Повтор меток модулей** — находка `duplicate_label` в `kitchen.checks`; импорт и `check_project` получают её из одного места.
- **Пенал в оба ряда:** ряд получает все пеналы своей стены из других рядов, даже если в нём есть свой пенал (сумма ряда, цоколь, столешница).

## Out of Scope

- Мелкие находки ревью, не названные в тикетах ниже: они остаются в `docs/reviews/2026-11-15/` до конца этапа.
- Вопросы мастеру из ревью (ручка ПММ, угловой в середине ряда и др.).

## Тикет 35 — Столешница по общей длине

**What to build:** столешница считается общей длиной без нарезки на куски; закупка — целые листы по общей длине.

**Blocked by:** 34

**Status:** done

**Решение мастера (2026-11-15, MVP):** рез столешницы на куски не нужен, достаточно общей длины. Листов = общая длина / длина листа столешницы, вверх до целого; цена — за лист, как сейчас. Какие модули лежат под столешницей — как сейчас (нижние модули рядов, без пенала и без смещения углового модуля соседней стены). Пропил между кусками больше не учитывается.

Это снимает находку B1 повторного ревью тикета 34 (неверные куски столешницы при угловом смещении в одном ряду): кусков больше нет.

- [x] Запись DECISIONS «Столешница» переписана на месте; записи о раскрое и закупке, упоминающие куски, — тоже
