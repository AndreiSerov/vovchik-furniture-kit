# Этап 7. ИИ-визуализация кухни

Статус: `ready-for-agent`. Вне MVP (PROGRESS, «Бэклог»), по просьбе мастера 2026-11-16, грилинг 2026-11-16.

## Problem Statement

Клиенту до замера трудно представить кухню в своей комнате. Мастер хочет быстро показать примерный вид: форму кухни по фото своей работы, материалы по фото образцов и комнату клиента по её фото.

## Solution

Скилл `kitchen-visualization` и его скрипт `scripts/visualize.py`. Скрипт отправляет фото комнаты, образец и фото материалов с пожеланиями мастера в сервис генерации (OpenAI или OpenRouter), ставит на результат водяной знак мастера и сохраняет **ИИ-визуализацию** (GLOSSARY) вместе с JSON, в котором записано, из чего она сделана.

## User Stories

1. Мастер присылает фото комнаты, образца кухни и материалов и добавляет пару слов («фасады как на втором фото, столешница под дуб»). В ответ приходит картинка кухни в этой комнате, без старой мебели.
2. Мастер выбирает форму кухни из каталога образцов: скилл показывает четыре формы брифа с фото работ мастера.
3. На каждой картинке стоит водяной знак мастера: имя и телефон.
4. Мастер пробует разные модели. Сервис и модель меняются в `.env` или флагом, код не меняется.
5. Скилл работает и вне мастерской, например в Codex с `uv` и сетью: ему нужны только фото и слова.

## Implementation Decisions

Ответы мастера 2026-11-16 (первые вопросы и грилинг):

- **Термин.** ИИ-визуализация — не проект, не вывод и не точный дизайн (виды и 3D кухни). В `kitchen status` и журнал заказа она не попадает.
- **Независимость.** Скилл не зовёт `kitchen` и не читает проект в БД. Скрипт использует стандартную библиотеку, Pillow и PyYAML (PEP 723: `uv run scripts/visualize.py`). Шрифт водяного знака DejaVuSans с кириллицей лежит в `assets/`.
- **Пользователь.** Только мастер: Telegram-чат или Codex. Клиент напрямую — позже, с веб-клиентом или приложением.
- **Сервисы.** `openai` по умолчанию: `POST /v1/images/edits`, модель `gpt-image-1`. Второй — `openrouter`: `POST /api/v1/chat/completions` с `modalities: ["image", "text"]`, модель `google/gemini-2.5-flash-image`, одна картинка на запрос. Сервис выбирается `--provider` или `VISUALIZATION_PROVIDER`, модель — `--model` или `VISUALIZATION_MODEL`. По умолчанию одна картинка, `quality=medium`, `size=auto`.
- **Ключи.** `.env` по классике: ближайший файл от текущей папки вверх. Уже заданная переменная окружения важнее `.env`. Ключи: `OPENAI_API_KEY`, `OPENROUTER_API_KEY`.
- **Фото клиента.** Согласие не спрашивается.
- **Промпт.** Убрать старую кухонную мебель и технику; стены, окна, двери, пол, потолок, трубы и ракурс оставить. Размеры не передаются: они сбивают модель, вид задают образец и материалы.
- **Куда сохранять.** Отдельно от выводов заказа: `orders/<заказ>/ai-visualization/`, без заказа — `orders/_ai-visualization/<дата>-<имя>/`, вне мастерской — `--out`. Входные фото копируются в `<out>/inputs/`.
- **Водяной знак мастера.** Имя и телефон из `--watermark` или `VISUALIZATION_WATERMARK`. Без знака скрипт останавливается до запроса. Логотип (`VISUALIZATION_WATERMARK_LOGO`, PNG) — позже, код его уже принимает.
- **Каталог образцов.** Тип кухни — это форма кухни из брифа: `straight`, `corner`, `u_shape`, `island`. Пока форм четыре, позже мастер может добавить ещё. Файл `catalog.yaml` и фото рядом с ним; папка — `--catalog`, `VISUALIZATION_CATALOG` или `workshop/sample-catalog/`. Пока фото нет, каталог — мок: ИИ-визуализация по образцу из него несёт «МОК-ДАННЫЕ — НЕ ДЛЯ КЛИЕНТА» на картинке и `warning` в JSON (принцип 4).

## Тикет 56 — Скилл `kitchen-visualization`: ИИ-визуализация по фото комнаты, образца и материалов

**Вывод.**

- PNG `<out>/visualization-<время>-<N>.png`, где N начинается с 1. Водяной знак стоит в правом нижнем углу, полупрозрачный, высота текста — 3 % короткой стороны картинки. С мок-каталогом вторая строка знака — «МОК-ДАННЫЕ — НЕ ДЛЯ КЛИЕНТА». Два запуска в одну секунду не перезаписывают друг друга.
- JSON `<out>/visualization-<время>.json`, тот же JSON идёт в stdout: `provider`, `model`, `prompt`, `shape`, `wishes`, `inputs` (роль и путь копии каждого фото), `images`, `watermark`, `mock`, `created`, `json`; при моке ещё `warning`.
- Ошибки идут в stderr по-русски с «Ошибка: », код возврата 2. Ошибкой считаются: неверные аргументы; нет фото комнаты или папки; нет ключа (с именем переменной); нет водяного знака; логотип не открывается; файл не найден или не картинка; неизвестная форма; у формы нет фото; каталог не разбирается; сервис вернул ошибку (код и текст сервиса); нет связи, таймаут или обрыв; ответ без картинки или с повреждённой картинкой. Всё, что можно проверить до платного запроса, проверяется до него.
- `catalog` печатает JSON: `mock`, при моке `warning`, `shapes[]` с полями `id`, `название`, `описание` и абсолютными путями `фото`. Пропавшие фото печатаются в `missing`.

**Проверки приёмки** (тесты с фейковым сервисом, `tests/test_visualize.py`):

1. Запрос OpenAI: multipart, все фото в `image[]`, комната первой; модель, промпт, `n`, `size`, `quality`; ключ в `Authorization`.
2. Запрос OpenRouter: JSON с текстом и картинками data-URI в порядке «комната, образец, материалы», `modalities`; `--n 2` — два запроса.
3. Промпт называет роль каждого фото, форму и пожелания и велит убрать старую мебель.
4. Ответы обоих сервисов разбираются в PNG. Ответ без картинки, повреждённая картинка, HTTP-ошибка, таймаут и обрыв дают ошибку по-русски.
5. Водяной знак меняет пиксели правого нижнего угла и не трогает левый верхний; мок-строка добавляет пиксели; логотип рисуется.
6. Без ключа, водяного знака, фото комнаты или папки, с плохим логотипом или неизвестной формой — ошибка до запроса.
7. `.env` берётся ближайший вверх от папки, переменная окружения важнее, комментарии в строке отбрасываются.
8. `catalog` читает формы и фото, плохой каталог даёт ошибку. Образец из мок-каталога даёт `mock`, `warning` и мок-строку на PNG. Свой образец мастера каталог не читает. Формы каталога мастерской совпадают с формами брифа.
9. Сохраняются PNG, JSON и копии входных фото, роль с `/` не ломает имя файла. Папки `orders/<заказ>/ai-visualization/` и `orders/_ai-visualization/` git не видит.
10. manual: живой вызов OpenAI с ключом из `.env` мастера (запускает агент по просьбе мастера).

## Testing Decisions

Сеть в тестах подменяется функцией отправки запроса. `http_send` проверяется на локальном сокете. Живой вызов — `manual`.
