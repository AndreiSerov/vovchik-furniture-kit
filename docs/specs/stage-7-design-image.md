# Этап 7. Картинка примерного дизайна кухни

Статус: `ready-for-agent`. Вне MVP (PROGRESS, «Бэклог»), по просьбе мастера 2026-11-16.

## Problem Statement

Клиенту до замера трудно представить кухню в своей комнате. Мастер хочет быстро показать примерный вид: тип кухни по фото его работы, материалы по фото образцов и комната клиента по её фото.

## Solution

Скилл `kitchen-design` и его скрипт `scripts/design_image.py`. Скрипт отправляет фото комнаты, фото образца и фото материалов с пожеланиями мастера в сервис генерации (OpenAI или OpenRouter), ставит на результат водяной знак мастера и сохраняет картинку с описанием того, из чего она сделана.

## User Stories

1. Мастер присылает фото комнаты, образца кухни и материалов, добавляет пару слов («угловая, фасады как на втором фото, столешница под дуб»). В ответ приходит картинка кухни в этой комнате.
2. Мастер выбирает тип кухни из каталога своих работ: скилл показывает список типов с фото-примерами.
3. На каждой картинке есть водяной знак мастера.
4. Мастер пробует разные модели. Сервис и модель меняются в `.env` или флагом, код не меняется.
5. Скилл работает и вне мастерской (Codex, ChatGPT, Telegram): ему нужны только фото и слова.

## Implementation Decisions

Ответы мастера 2026-11-16:

- **Независимость.** Скилл не зовёт `kitchen` и не читает проект в БД. Скрипт зависит только от стандартной библиотеки и Pillow (PEP 723: `uv run scripts/design_image.py`). Шрифт водяного знака (DejaVuSans, с кириллицей) лежит в `assets/`.
- **Сервисы.** `openai` (по умолчанию, `POST /v1/images/edits`, модель `gpt-image-1`) и `openrouter` (`POST /api/v1/chat/completions` с `modalities: ["image", "text"]`, модель `google/gemini-2.5-flash-image`). Сервис выбирается флагом `--provider` или `DESIGN_PROVIDER`, модель — флагом `--model` или `DESIGN_MODEL`.
- **Ключи.** `.env` по классике: файл ищется от текущей папки вверх. Уже заданная переменная окружения важнее `.env`. Ключи: `OPENAI_API_KEY`, `OPENROUTER_API_KEY`.
- **Фото клиента.** Согласие не спрашивается. Фото уходят в выбранный сервис.
- **Куда сохранять.** В мастерской — `orders/<заказ>/design/`, вне её — то, что передано в `--out`. Входные фото копируются в `<out>/inputs/`.
- **Водяной знак мастера.** Текст из `--watermark` или `DESIGN_WATERMARK`. Без текста скрипт останавливается с ошибкой: картинка без знака не выходит. Можно добавить логотип (`DESIGN_WATERMARK_LOGO`, PNG).
- **Каталог.** Фото работ мастера: `catalog.yaml` и фото рядом с ним. Папка задаётся флагом `--catalog` или `DESIGN_CATALOG`, в мастерской — `workshop/design-catalog/`. Пока фото нет, каталог — мок (`mock: true`). Картинка по образцу из мок-каталога несёт «МОК-ДАННЫЕ — НЕ ДЛЯ КЛИЕНТА» в водяном знаке и в JSON (принцип 4).

## Тикет 56 — Скилл `kitchen-design`: картинка по фото комнаты, образца и материалов

**Вывод.**

- PNG `<out>/design-<время>-<N>.png`, где N начинается с 1. Водяной знак в правом нижнем углу, полупрозрачный, высота текста — 3 % короткой стороны картинки. С мок-каталогом вторая строка знака — «МОК-ДАННЫЕ — НЕ ДЛЯ КЛИЕНТА».
- JSON `<out>/design-<время>.json` и тот же JSON в stdout: `provider`, `model`, `prompt`, `kitchen_type`, `wishes`, `inputs` (роль и путь копии каждого фото), `images`, `watermark`, `mock`, `created`.
- Ошибки идут в stderr по-русски, код возврата 2: нет ключа (какую переменную задать), нет водяного знака, нет фото комнаты, файл не найден или не картинка, сервис вернул ошибку (код и текст сервиса), ответ без картинки.
- `catalog` печатает JSON: `mock`, `types[]` с `id`, `название`, `описание` и абсолютными путями `фото`. Пропавшее фото печатается в `missing`.

**Проверки приёмки** (тесты с фейковым сервисом, `tests/test_design_image.py`):

1. Запрос OpenAI: multipart, все фото в `image[]` (комната первой), модель и промпт; ключ в `Authorization`.
2. Запрос OpenRouter: JSON с текстом и картинками data-URI в порядке «комната, образец, материалы», `modalities`.
3. Промпт называет роль каждого фото, тип кухни и пожелания мастера.
4. Ответы обоих сервисов разбираются в PNG; ответ без картинки и HTTP-ошибка дают понятную ошибку.
5. Водяной знак меняет пиксели правого нижнего угла и не меняет левого верхнего.
6. Без ключа или без водяного знака — ошибка до запроса.
7. `.env` читается вверх от папки; переменная окружения важнее.
8. `catalog` читает типы и фото. Образец из мок-каталога даёт `mock: true` и строку МОК в знаке.
9. Сохраняются PNG, JSON и копии входных фото.
10. manual: живой вызов OpenAI с ключом из `.env` (ставит мастер, запускает агент по просьбе мастера).

## Testing Decisions

Сеть в тестах подменяется функцией отправки запроса. Живой вызов — `manual`.
