## Новые мелкие находки (в список на конец этапа, не блокируют)

1. **Отрицательные значения в `labor.yaml` и `pricing.yaml` дают правдоподобную, но неверную цену без ошибки.** Подтверждено. Причина в `engine/kitchen/models.py:534-549,589-591`: поля типа `Num` без ограничений. Это код вне дифа и общий пробел для всех цен мастерской, смета — первый потребитель, поэтому не блокирую. Стандарт «Нет молчаливо неверного вывода». На малом проекте `ставка_в_час: -1000` даёт труд −15796.07 и цену 35000 вместо 67000; `доставка_материалов: -1000000` даёт цену −936000. Механическая проверка: `Field(ge=0)` на этих полях и тест загрузки.
   ```python
   def test_negative_rate_is_a_workshop_error(small):
       edit_workshop(small, "labor.yaml", "ставка_в_час: 1000", "ставка_в_час: -1000")
       with pytest.raises(KitchenError):
           api.estimate_from_order(ORDER, small)  # сейчас: labor.total == -15796.07, price == 35000
   ```

2. **`ставка_в_час: .inf` или `.nan` роняют смету не русской ошибкой.** Подтверждено. `.inf` даёт `decimal.InvalidOperation` из `_money` (`estimate.py:41`), `.nan` — `ValueError: cannot convert NaN to integer` из `RoundingRule.apply`. `kitchen estimate petrov` выходит с кодом 1, пустым выводом и необработанным исключением. Корень тот же, что в пункте 1, вход нереалистичный. Проверка: `allow_inf_nan=False` на `Num`.
   ```python
   def test_infinite_rate_is_a_workshop_error(small):
       edit_workshop(small, "labor.yaml", "ставка_в_час: 1000", "ставка_в_час: .inf")
       with pytest.raises(KitchenError):
           api.estimate_from_order(ORDER, small)  # сейчас: decimal.InvalidOperation
   ```

3. **Пробел тестов: связь операции с её нормой проверена только для распила.** Подтверждено мутацией: замена в `estimate.py:123` на `("measuring", "site_visit", ...)` проходит все 26 тестов сметы, потому что `выезд` и `замер` оба равны 90, а `test_norm_swap_changes_only_its_line_and_total` меняет одну норму. Код сейчас верен: моя проба подменила каждую из 11 норм на 7.5, и менялась только своя строка. Нужна параметризация теста по всем 11 парам «ключ YAML → операция».

4. **Пробел тестов: врезки мойки и варочной не различаются.** Подтверждено мутацией: `Decimal(count("sink"))` в строке варочной (`estimate.py:118`) проходит все тесты, потому что в обоих фикстурах ровно одна мойка и одна варочная. Код верен: проба с двумя мойками без варочной дала 2 и 0. Нужен тест на проекте с мойкой без варочной.

5. **Устаревший литерал в тесте.** `tests/test_estimate.py:219` складывает ожидаемую сумму с `Decimal("15796.06")`, хотя итог труда теперь 15796.07. Тест проходит только за счёт округления вверх и допуска `abs=0.02` в строке 222. Лучше брать `result.labor.total` и допуск 0.005. Кроме того, `test_labor_total_is_sum_minutes_times_rate` (строки 155-158) повторяет утверждение строки 151.

6. **`base_sink` без мойки в `appliances` даёт врезку 0 без предупреждения.** Подтверждено пробой: один `base_sink` 600 без техники — `sink_cutout: 0`, в `warnings` только «без задней стенки». Это соответствует решению мастера «по прибору проекта», но цена молча теряет час работы. То же с варочной. Предлагаю дописать в `DECISIONS.md`, тема «Смета», с ПРОВЕРИТЬ МАСТЕРУ: нужно ли предупреждение.
