# Решения агента по поручению мастера (2026-11-15)

Мастер поручил агенту дописать открытые тикеты MVP самому: «делай МВП, далее исправим». Ниже — что агент решил вместо вопросов мастеру. Каждое решение записано в своём тикете в блоке «Решения агента (MVP…)» и сборку не держит. После MVP мастер проходит этот список; ответ, который меняет решение, становится новым тикетом.

Тикеты уборки (45–48) дописывают сюда вопросы, которые меняют числа или вывод для клиента или цеха.

| Тикет | Что решено | Почему так для MVP |
|---|---|---|
| 22 | Этапы `сборка` — фиксированный набор движка; без `ставится` — «цех»; формулировки строк шагов | Меньше данных для мока, ошибки ловятся при загрузке |
| 40 | `выезд` обязателен; без брифа шапка из «—»; навесы только в «Фурнитуре для монтажа» | Без повторов в чек-листе |
| 23 | Пересечение верхних рядов в углу без верхнего углового — ошибка `corner_overlap` | Проект с таким углом не собрать |
| 45 | Предупреждение «нет мойки»; `ножки.высота: 0` — ошибка; `мин_размер_детали` 50 мм (МОК); диапазоны меток КП внутри ряда и буквы; бутылочница «с выдвижным фасадом»; `type: other` клиенту без модели | Отсечь невозможные детали и непонятный клиенту текст |
| 46 | Перемычка 0 мм — не пересечение; отступ правых чашек от ближней кромки; полки и шаг 96–128 как есть | Числа модели не меняются |
| 36 | Коды выхода 1/2, порядок находок, «Замечаний нет.», одна проверка с импортом | Агент отличает ошибки проекта от сбоя |
| 27 | Агент пишет `project.json` сам по словам мастера; относительные правки переспрашивает; 3D по просьбе | Принцип 1, нет раскладки |
| 28 | Порядок `status → check → production`; устаревшее пересчитывает без вопроса; мок в документах цеха — предупреждение «сверьте перед распилом» | Документы цеха — для мастера |
| 29 | Срок КП всегда спрашивает; «экономию» предлагает при цене выше бюджета; смета — внутренний документ | Принцип 4 и решение по КП |
| 30 | Значения полей холодильника, `workzone`, `installation`; `who_buys: master`; метраж вилки из `check_brief.py`; `brief save` пишет `status.md` | Старые брифы проходят |
| 43 | Голос — первое лицо без имени; сравнение бюджета с вилкой словами; пороги `min_budget_*` остаются | Минимум правок скилла |
| 44 | Бриф по имени, при совпадении — вопрос мастеру и команда из ошибки | Без правки движка |
| 31 | Пятый скилл `kitchen-order`; проверка триггеров свежим субагентом | Фраза ведёт ровно к одному скиллу |
| 49 | Таблица следующего шага; поиск без падежных окончаний | Сценарий «продолжи заказ Петрова» |

## После MVP

- Метраж вилки считает `check_brief.py` скилла (`base_depth_mm` из `settings.json`), а не движок — перенести формулу в движок (принцип 2).
- Деньги `min_budget_*` в `settings.json` вне `pricing.yaml`.
- Кухня на цокольной коробке (`ножки.высота: 0`).
