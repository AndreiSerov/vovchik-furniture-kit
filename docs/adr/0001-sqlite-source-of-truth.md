# 0001. Заказы, версии проекта и журнал хранятся в SQLite

Статус: принято, 2026-11-13.

## Контекст

ТЗ задумывало `project.json` в папке заказа как единственный источник правды. В заказах будут персональные данные клиентов, их нельзя держать в git. Нужны неизменяемые версии проекта и учёт того, какой вывод посчитан из какой версии.

## Решение

- Одна БД SQLite в `$KITCHEN_HOME/orders/kitchen.db`, в `.gitignore`. Путь переопределяется `KITCHEN_DB`.
- В БД лежат заказы (номер, клиент, контакты, адрес), бриф, все версии проекта (JSON с номером), журнал и учёт выводов.
- Источник правды — текущая версия проекта в БД. Номер версии ставит движок при импорте; неизменённый проект новой версии не создаёт.
- Агент меняет проект через `kitchen export` → правка `project.json` → `kitchen import`. Импорт проверяет схему и правила, при ошибке отклоняется. `kitchen diff` показывает разницу версий по-человечески.
- `status.md` руками не пишут: его собирает `kitchen status` из журнала. Скиллы дописывают журнал через `kitchen log`.
- Файлы выводов (PDF, HTML, `purchase.md`) лежат в `orders/<заказ>/out/`, в `.gitignore`, и хранят версию-источник.
- Тестовый заказ `2026-047-petrov` лежит в git как фикстура `project.json` и импортируется в БД.

## Последствия

- Принцип 3 ТЗ читается так: «текущая версия проекта в БД — единственный источник правды».
- Слой хранения нужен с этапа 0 (задачи 0.4, 0.5), а этап 5.3 сужается до устаревших выводов.
- Точечные команды правки (`kitchen module set …`) отложены: вернёмся, если модели портят JSON.
