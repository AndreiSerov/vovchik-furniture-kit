# 0002. Движок из трёх слоёв: API → CLI → скиллы

Статус: принято, 2026-11-13.

## Контекст

Скиллами будут пользоваться разные модели: Claude, GPT в Hermes, Codex, Qwen. Позже появится бот на LangChain (Telegram или веб). Модели слабее держат длинные инструкции и могут пересчитывать числа сами.

## Решение

1. **`kitchen.api`** — Python-функции на pydantic-моделях. Это единственное место логики и основная точка тестов. LangChain-инструменты потом лягут прямо на него.
2. **CLI `kitchen`** — тонкая обёртка над API. По умолчанию печатает готовый к показу текст по-русски, с `--json` отдаёт ровно результат API. В любом выводе с моком — поле `mock: true` и плашка «МОК-ДАННЫЕ — НЕ ДЛЯ КЛИЕНТА».
3. **Скиллы** вызывают CLI и пересказывают результат. Числа переносят как есть, формул не содержат.

`kitchen` ставится в систему (`uv tool install -e .`) и находит мастерскую по `KITCHEN_HOME`, иначе ищет корень репо вверх от текущей папки.

## Последствия

- MCP-сервер в МВП не делаем.
- Тесты логики идут через API; CLI проверяется только контрактными тестами.

## Слои движка

Дополнено 2026-11-19 (тикет 67 этапа 9). Три слоя из заголовка (API → CLI → скиллы) — внешний стек; таблица ниже — слои движка внутри пакета `kitchen`. Слои проверяет import-linter в `scripts/check`, контракты лежат в `pyproject.toml` (`[tool.importlinter]`). Модуль импортирует только слои ниже себя; модули одного слоя друг от друга не обязаны быть независимы.

| Слой (сверху вниз) | Модули |
|---|---|
| CLI | `kitchen.cli` |
| API | `kitchen.api`, `kitchen.calculation` (с тикета 69) |
| Рендер | `cutting_pdf`, `edging_pdf`, `drilling_pdf`, `assembly_pdf`, `trip_pdf`, `quote_pdf`, `views_pdf`, `views_html`, `scene3d`, `pdf` |
| Домен | `assembly`, `brief`, `checks`, `common`, `cutting`, `drilling`, `economy`, `estimate`, `geometry`, `models`, `parts`, `placement`, `project`, `purchase`, `quote`, `store`, `tall`, `trip`, `views`, `workshop` |
| Основа | `errors`, `format`, `formulas`, `metrics`, `ral`, `result` |

`kitchen.skill_lint` импортирует `kitchen.cli` и в слои не входит. `kitchen.metrics` — основа без отрисовки: шрифты, размер и область страницы, перенос строк и штамп вывода `Stamp`; `kitchen.pdf` реэкспортирует эти имена.

Остальные контракты:

- «CLI ходит только в api»: `kitchen.cli` прямо не импортирует ничего, кроме `api`, `errors`, `result`; косвенные цепочки допустимы.
- «Писатели независимы»: семь `*_pdf` и `views_html` не импортируют друг друга.
- «Расчёты не ходят в БД»: расчётные модули домена прямо не импортируют `store`, `api` и `calculation`.
