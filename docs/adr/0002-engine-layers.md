# 0002. Движок из трёх слоёв: API → CLI → скиллы

Статус: принято, 2026-11-13.

## Контекст

Скиллами будут пользоваться разные модели: Claude, GPT в Hermes, Codex, Qwen. Позже появится бот на LangChain (Telegram или веб). Модели слабее держат длинные инструкции и могут пересчитывать числа сами.

## Решение

1. **`kitchen.api`** — Python-функции на pydantic-моделях. Это единственное место логики и основная точка тестов. LangChain-инструменты потом лягут прямо на него.
2. **CLI `kitchen`** — тонкая обёртка над API. По умолчанию печатает готовый к показу текст по-русски, с `--json` отдаёт ровно результат API. В любом выводе с моком — поле `mock: true` и плашка «МОК-ДАННЫЕ — НЕ ДЛЯ КЛИЕНТА».
3. **Скиллы** вызывают CLI и пересказывают результат. Числа переносят как есть, формул не содержат.

`kitchen` ставится в систему (`uv tool install -e .`) и находит мастерскую по `KITCHEN_HOME`, иначе ищет корень репо вверх от текущей папки.

## Последствия

- MCP-сервер в МВП не делаем.
- Тесты логики идут через API; CLI проверяется только контрактными тестами.
