# vovchik-furniture-kit glossary

Code, docs and logs use these terms. `/grill-with-docs` adds to this file as terms get settled.
Человеку показываем русский термин, в коде используем английский.

| Term | Code | Meaning | Avoid |
|---|---|---|---|
| Мастер | master | Мебельщик-одиночка, пользователь системы: сам общается с клиентом, закупает, пилит, кромит, сверлит, собирает | салон, дизайнер, менеджер |
| Мастерская | workshop | Данные мастера в YAML: оборудование, конструкция, материалы, фурнитура, труд, цены, техника | настройки, конфиг |
| Мок | mock | Файл мастерской с `mock: true`: значения-заглушки, которые мастер ещё не заменил. Любой вывод, посчитанный с моком, несёт пометку «МОК-ДАННЫЕ — НЕ ДЛЯ КЛИЕНТА» | тестовые данные, демо |
| Заказ | order | Одна кухня одного клиента. Номер `ГГГГ-NNN-фамилия`, например `2026-047-petrov` | проект (о заказе целиком) |
| Бриф | brief | Требования клиента до замера, собранные скиллом `kitchen-brief` | ТЗ, анкета |
| Проект | project | Конструкция кухни заказа: стены, модули по порядку, материалы, наполнение, техника | дизайн, раскладка (о проекте целиком) |
| Версия проекта | project version | Неизменяемая копия проекта с номером. Новая версия появляется при каждом импорте изменённого проекта | ревизия, редакция |
| Стена | wall | Стена помещения с меткой `A`, `Б`. Модули на стене идут по порядку от начала стены | сторона |
| Ряд | row | Нижний или верхний ряд модулей на стене. Пенал входит в оба ряда | ярус, уровень |
| Пустое место | gap | Участок ряда заданной ширины без деталей: место под отдельностоящую технику или над окном. Метка `ПМ1`. Входит в сумму ряда, не входит в цоколь, шину и LED, в столешницу — только с `under_countertop` | ниша, проём |
| Модуль | module | Один шкаф проекта с меткой: `П1` пенал, `Н1` нижний, `В1` верхний | шкаф, блок, секция, корпус (о модуле целиком) |
| Шаблон | template | Правило движка, которое превращает модуль в детали и фурнитуру: `base_door`, `wall_lift`, `tall_oven` и др. | тип шкафа, пресет |
| Деталь | part | Одна плоская деталь из листа или фасад. Имеет маркировку, размеры, материал, кромку по 4 сторонам и положение в модуле | панель, заготовка |
| Маркировка | part ID | Уникальная метка детали вида `Н1-бок-Л`: модуль, имя, уточнение | артикул, код |
| Фурнитура | hardware | Покупные изделия из `hardware.yaml`: петли, направляющие, конфирматы, опоры и т. д. | комплектующие |
| Кромка | edge | ПВХ-кромка на торце детали. Кромление — её приклейка | обкладка |
| Угловое смещение | corner offset | Длина соседней стены, которую занимает угловой модуль, хотя он числится на другой стене | заход, нахлёст |
| Расстановка | placement | Где стоит каждый модуль проекта в комнате: стена, отступ от её начала, поворот стены, коробка модуля. Стены связаны углами (угловыми модулями) в одну цепочку; начало координат — начало первой стены цепочки на полу | раскладка (это черновик проекта по брифу, 5.2), планировка |
| Коробка модуля | module box | Габарит модуля в расстановке: корпус плюс фасад, то, что видит клиент. Вне коробки только задняя стенка ХДФ | габарит корпуса (без фасада) |
| Виды кухни | kitchen views | PDF `kitchen 3d`: план сверху и вид на каждую стену спереди по расстановке — рабочий чертёж мастера с метками, фасадами, техникой, цепочками ширин и высотами | чертёж (уточнять), развёртка |
| Сцена | scene | JSON-список объектов расстановки для видов (`ViewScene`) и для 3D кухни (`Scene3D`, из тех же видов): модули, стены, пол (детали — по контракту), у каждого положение, размер, поворот, цвет, признак фасада | 3D-модель (о данных, а не о HTML) |
| 3D кухни | kitchen 3D | HTML-страница `kitchen-3d.html`: `kitchen 3d` пишет её рядом с PDF видов. Кухня объёмом в браузере, без сети (three.js встроен); камера и высоты — DECISIONS «3D в HTML (тикет 42)»; нажатие на модуль показывает его подпись. Вывод со своей версией-источником | чертёж (это виды кухни), 3D-модель (о данных) |
| Ниша | niche | Проём модуля под встроенную технику | отсек |
| Раскрой | cutting layout | Гильотинная укладка деталей на листы с порядком резов. Карта раскроя — его PDF | раскладка (о листе), нарезка |
| Присадка | drilling | Отверстия в деталях под конфирматы, петли, планки и др. Карта присадки — её PDF: схема детали, отверстия, размеры от базовых кромок | сверловка, разметка (о карте целиком) |
| Пласть | face | Большая плоская сторона детали; у листовой детали их две | плоскость, лицо (о детали) |
| Торец | end | Узкая грань детали по её толщине; на нём кромка, в него сверлят под конфирмат | кромка (о грани, а не о ПВХ-ленте) |
| Соединение | joint | Деталь торцом крепится конфирматами к пласти другой детали: дно к боковине. Из соединений считаются конфирматы и их отверстия | стык, крепёж (о соединении) |
| Сторона петель | hinge side | С какой стороны двери петли: `left` или `right` (`contents.hinge_side`); ответные планки — на боковине той же стороны | сторона открывания |
| Ряд полкодержателей | shelf pin row | Вертикальный ряд отверстий с шагом 32 на внутренней пласти боковины, спереди или сзади, с отверстием под полку (центр на радиус штыря ниже полки); у дна или крыши ряд сдвигается на целые шаги, отверстие под полку остаётся в ряду. На полку — четыре ряда | перфорация |
| Базовая кромка | base edge | Кромка детали, от которой отмеряются отверстия на карте присадки; у детали их две, правило — в `construction.yaml` | нулевая кромка |
| Чек-лист выезда | trip checklist | PDF с галочками «☐»: шапка заказа из брифа, модули, общие позиции, фурнитура «объект», техника клиента, инструмент и расходники (`equipment.yaml`, `выезд`) | список для монтажа, накладная |
| Сборочный лист | assembly sheet | PDF по модулям: детали, вся фурнитура модуля и шаги сборки по шаблону и соединениям. Фурнитура «объект» (опоры, ручки, навесы) стоит в списке с пометкой «на объекте» и шага сборки не имеет; её же берёт чек-лист выезда | инструкция по сборке, спецификация |
| Закупка | purchase list | Что купить: целые листы, метраж кромки, фурнитура упаковками, по магазинам | заказ поставщику |
| Смета | estimate | Внутренний расчёт мастера: себестоимость, труд, наценка, цена | калькуляция |
| Замена | economy rule | Правило из `economy.yaml`: что в модулях проекта заменить на более дешёвое (карусель на полку, ящики на двери и т. д.), с текстом для клиента. Применяется ко всем подходящим модулям | апгрейд, опция |
| Вариант «экономия» | economy variant | Смета копии текущей версии проекта со всеми предложенными заменами и разница с ценой «как в проекте». Копия версией не становится. | дешёвый вариант, эконом-класс |
| КП | quote | Коммерческое предложение клиенту: итог, предоплата, сроки, без себестоимости и наценки | счёт, смета (о документе клиенту) |
| Вывод | output | Результат, посчитанный из версии проекта: файл или JSON. Хранит версию-источник | отчёт, артефакт |
| Устаревший вывод | stale output | Вывод, чья версия-источник старше текущей версии проекта | неактуальный |
| Журнал | log | Записи заказа: что сделано, решения клиента, что дальше. Из него `kitchen status` собирает `status.md` | история, лента |
| Форма кухни | kitchen shape | Как кухня стоит в комнате: прямая (`straight`), угловая (`corner`), П-образная (`u_shape`), только остров (`island`). Задаётся в брифе; по ней же выбирают образец | тип кухни, планировка |
| Образец | sample | Фото готовой кухни, по которому ИИ-визуализация берёт расстановку и стиль: фото работы мастера из каталога образцов или фото, присланное мастером | пример, референс |
| Каталог образцов | sample catalog | Фото работ мастера по формам кухни, из которых мастер выбирает образец | галерея, портфолио |
| ИИ-визуализация | AI visualization | Картинка примерного вида кухни в комнате клиента. Её рисует нейросеть по фото комнаты, образцу и фото материалов. Не в масштабе, с проектом не связана и выводом не является; на ней водяной знак мастера (имя и телефон) | дизайн (это проект), рендер, 3D (это 3D кухни и виды кухни) |

## Сокращения маркировок

Маркировка детали — `<модуль>-<сокращение имени>[-<уточнение>]`, например `Н1-бок-Л`.

| Сокращение | Имя детали | Уточнения |
|---|---|---|
| бок | боковина | `Л` — левая, `П` — правая |
| дно | дно | — |
| царга | царга | номер: 1 — передняя (у фасада), 2 — задняя |
| полка | полка | номер полки, если полок несколько |
| зад | задняя стенка | — |
| фасад | фасад | `Л` — левый, `П` — правый, для ящиков номер снизу (у одной двери уточнения нет) |
| крыш | крыша | — |
| загл | заглушка | — |
| дно-ниши | дно ниши | — |
| перег | перегородка ниши | номер |
| дно-выт | передняя планка дна вытяжки | номер детали |
| дно-ящ | дно ящика | номер ящика снизу |
| зад-ящ | задняя стенка ящика | номер ящика снизу |

Стороны кромки детали: `L1`/`L2` — длинные стороны (по длине детали), `W1`/`W2` — короткие.
Стороны считаются по осям детали, а не по осям модуля, и правило одно для любой ориентации:
`L1` — на положительном конце оси ширины, `L2` — на отрицательном; `W1` — у начала оси длины,
`W2` — у её конца. Для детали, у которой ось ширины `y`, `L1` — сторона, обращённая в комнату.
Шаблоны называют кромимую грань геометрически (`+y` — передняя, в комнату) и не угадывают
L1/L2/W1/W2: их выбирает `make_part` после выбора оси длины. Нетекстурная деталь, у которой
глубина больше ширины (дно и полка узкого модуля), получает длину по глубине, и её передняя
кромка оказывается на `W2`, а не на `L1`.
