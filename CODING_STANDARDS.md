# Стандарты кода

Правила-суждения для ревьюера: их не проверит ни линтер, ни тест. Механические правила живут в `scripts/check` (ruff, `tests/test_structure_guards.py`), здесь их нет.

## Одно правило — одно место

Один вопрос предметной области решает одна функция или одна запись реестра; остальной код её зовёт. Находка — второе место, которое отвечает на тот же вопрос по-своему, даже если сейчас ответы совпадают.

Прошлые находки этого вида:
- разбор номера заказа жил в `store.find_order` и `_resolve_for_brief` (тикет 04) — теперь `store.parse_query`;
- запрет поворота детали: раскрой смотрел текстуру листа, проверка проекта — текстуру детали (тикет 12) — теперь `checks.part_fit_findings`;
- ниша техники: проверка считала её иначе, чем шаблон (тикет 10) — теперь `parts.built_niche`;
- свойства шаблона по его имени (`"tall_oven"`) вместо реестра `TEMPLATES` (ревью этапа 1).

## Данные мастерской, а не литералы

Число, id позиции или правило, которое мастер может захотеть поменять, читается из `workshop/*.yaml` (принцип 2 в `AGENTS.md`). Находка — такое значение константой в движке.

## Нет молчаливо неверного вывода

Случай, который движок не умеет посчитать правильно, даёт русскую ошибку или находку, а не правдоподобное число. Ревьюер ищет вход, на котором вывод выглядит нормально, но неверен: деталь на миллиметры больше номинала, недокупка, закрытая подпись на карте.

## `DECISIONS.md` без противоречий

Новая запись стоит в своей теме и заменяет устаревшую, а не дописывается рядом. Находка — две записи, которые отвечают на один вопрос по-разному, или запись, которую код уже не выполняет.
