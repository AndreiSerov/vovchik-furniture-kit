# kitchen-visualization

ИИ-визуализацию рисует сервис генерации (OpenAI или OpenRouter) через скрипт `scripts/visualize.py` этого скилла. Скрипту нужны только фото и слова мастера: движок, проект и замер ему не нужны. Скрипт ставит водяной знак мастера (имя и телефон) и печатает JSON с описанием результата. Пути и признаки бери из этого JSON как есть.

С тобой говорит мастер. Клиенту ИИ-визуализацию пересылает он сам.

Скрипт запускай из папки, где лежит `.env` мастера, или из любой папки под ней:

```
uv run <папка скилла>/scripts/visualize.py catalog
uv run <папка скилла>/scripts/visualize.py generate --room <фото> [--shape <форма>] [--sample <фото>] [--material <роль>=<фото>]... [--wishes "<пожелания>"] --out <папка>
```

`--help` у скрипта перечисляет все флаги. Мастер хочет попробовать другую модель — передай `--provider` и `--model`.

## Правила

- **Фото комнаты обязательно.** Без него ИИ-визуализацию не делай: попроси фото.
- **Согласие клиента не спрашивай.** Так решил мастер: фото уходят в сервис без вопроса.
- **Форма кухни — одна из четырёх, как в брифе:** `straight` прямая, `corner` угловая, `u_shape` П-образная, `island` только остров. Остров у прямой или угловой кухни скажи в `--wishes` словами.
- **Без размеров.** Размеры сбивают модель: вид задают только образец и фото материалов. Миллиметры, метры и длины стен из слов мастера в `--wishes` не переноси. Если мастер их назвал, скажи одной фразой, что размеры в ИИ-визуализацию не идут.
- **Пожелания — о виде и материалах,** словами мастера: «фасады без ручек», «столешница под дуб», «угловая с островом».
- **Роль материала — по-русски и коротко:** `фасады`, `столешница`, `фартук`, `корпус`, `ручки`. Если непонятно, к чему относится фото, спроси одним вопросом.
- **Мок клиенту не уходит.** В JSON есть `"warning": "МОК-ДАННЫЕ — НЕ ДЛЯ КЛИЕНТА"`, и та же строка стоит на картинке. Скажи мастеру: «Образец взят из мок-каталога (MOCKS.md, каталог образцов) — замените фото своими работами». Такую картинку клиенту не отправляй, даже если просят переслать через Telegram или VK.

## Шаги

1. **Собери фото.** Нужны фото комнаты, образец (своё фото мастера или форма из каталога), фото материалов с ролями и пожелания. Фото из Telegram скачай вложением и работай с локальным путём. Шаг готов, когда у тебя есть путь к фото комнаты и ты знаешь, откуда взять образец: путь к фото или форма.
2. **Каталог — если мастер выбирает форму.** Запусти `catalog`. Покажи `название` и `описание` каждой формы и отправь мастеру её `фото`. Если у формы список `фото` пуст, скажи, что фото работ этой формы ещё нет, и попроси прислать образец. Шаг готов, когда выбрана форма с фото или прислан образец.
3. **Выбери папку.** ИИ-визуализация лежит отдельно от выводов заказа.
   - Рядом есть `orders/` (мастерская), мастер назвал заказ — `--out orders/<заказ>/ai-visualization`.
   - Рядом есть `orders/`, заказа нет — `--out orders/_ai-visualization/<ГГГГ-ММ-ДД>-<имя клиента латиницей>`.
   - Вне мастерской — папка, которую назвал мастер, иначе `--out ai-visualization/<ГГГГ-ММ-ДД>-<имя>` в текущей папке.
   Шаг готов, когда папка выбрана.
4. **Сделай картинку.** Запусти `generate`: образец из каталога — `--shape <форма>` без `--sample`, своё фото мастера — `--sample <фото>` (и `--shape`, если форма известна). Готово, когда код выхода 0 и в stdout есть JSON с `images`. Код 2 — покажи текст ошибки как есть. Если в тексте названа переменная `.env`, скажи мастеру добавить её в `.env` и остановись.
5. **Покажи результат.** Отправь мастеру каждую картинку из `images`, в Telegram — файлом в ответе. Подпиши: «ИИ-визуализация, примерный вид: размеры и цвета уточняются на замере». Назови `model` и путь к JSON. Если в JSON есть `warning`, добавь фразу из правила «Мок клиенту не уходит». Шаг готов, когда мастер получил каждую картинку из `images` с подписью.
6. **Правки.** «Светлее фасады», «без верхних шкафов» и подобное — повтори шаг 4 с теми же фото и новыми `--wishes`. Старые картинки останутся, у каждой своё время в имени. Шаг готов, когда мастер получил новую картинку или сказал, что правок больше нет.
