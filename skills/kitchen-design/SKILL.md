# kitchen-design

Картинку рисует сервис генерации (OpenAI или OpenRouter) через скрипт `scripts/design_image.py` этого скилла. Скрипту нужны только фото и слова мастера: движок `kitchen`, проект и замер не нужны. Скрипт ставит водяной знак мастера и пишет JSON с описанием результата. Пути и признаки бери из этого JSON как есть.

Скрипт запускай из папки, где лежит `.env` мастера (или из любой папки под ней):

```
uv run <папка скилла>/scripts/design_image.py catalog
uv run <папка скилла>/scripts/design_image.py generate --room <фото> [--sample <фото>] [--sample-type <id>] [--material <роль>=<фото>]... [--type "<тип>"] [--wishes "<пожелания>"] --out <папка>
```

Ключи, сервис, модель и текст водяного знака скрипт берёт из `.env` (`OPENAI_API_KEY`, `OPENROUTER_API_KEY`, `DESIGN_PROVIDER`, `DESIGN_MODEL`, `DESIGN_WATERMARK`). Мастер пробует другую модель — передай `--provider` и `--model`.

## Правила

- **Фото комнаты обязательно.** Без него картинку не делай: попроси фото.
- **Согласие клиента не спрашивай.** Мастер так решил: фото уходят в сервис без вопроса.
- **Пожелания — словами мастера.** В `--wishes` передай его слова как есть, а в `--type` — тип кухни так, как он его назвал.
- **Роль материала — по-русски и коротко:** `фасады`, `столешница`, `фартук`, `корпус`, `ручки`. Если непонятно, к чему относится фото материала, спроси одним вопросом.
- **Мок клиенту не уходит.** В JSON стоит `"mock": true`, а на картинке видна строка «МОК-ДАННЫЕ — НЕ ДЛЯ КЛИЕНТА». Скажи мастеру: «Образец взят из мок-каталога (MOCKS.md, каталог образцов) — замените фото своими работами». Такую картинку клиенту не отправляй, даже если просят переслать через Telegram или VK.

## Шаги

1. **Собери фото.** Нужны: фото комнаты, образец кухни (своё фото или тип из каталога), фото материалов с ролями и пожелания. Фото из Telegram скачай вложением и работай с локальным путём. Шаг готов, когда у тебя есть путь к фото комнаты и ты знаешь, откуда взять образец.
2. **Каталог — если мастер выбирает тип.** Запусти `catalog`. Покажи `название` и `описание` каждого типа и отправь мастеру его `фото`. Если у типа список `фото` пуст, скажи, что фото работ ещё нет, и попроси прислать образец. Шаг готов, когда выбран `id` типа или прислано фото образца.
3. **Выбери папку результата.** Если рядом есть `orders/<заказ>/` и мастер назвал заказ, то `--out orders/<заказ>/design`. Иначе — `--out kitchen-design/<имя клиента или дата>`. Шаг готов, когда папка выбрана.
4. **Сделай картинку.** Запусти `generate`. Готово, когда код выхода 0 и в stdout есть JSON с `images`. Код 2 — покажи текст ошибки как есть. Если в тексте названа переменная `.env`, скажи мастеру добавить её в `.env` и остановись.
5. **Покажи результат.** Отправь каждую картинку из `images` (в Telegram — файлом в ответе). Подпиши: «Примерный вид, не проект: размеры и цвета уточняются на замере». Назови `model` и путь к JSON. Если `mock` равен `true`, добавь фразу из правила «Мок клиенту не уходит».
6. **Правки.** «Светлее фасады», «без верхних шкафов» и подобное — повтори шаг 4 с теми же фото и новыми `--wishes`. Старые картинки не удаляй: у каждой своё время в имени.
